# DEEPSIGHT 1.1.0 — implementation status and roadmap

Validation for this release: [QA.md](QA.md). What changed: [../CHANGELOG.md](../CHANGELOG.md).

**Status** says only what the prototype does today and how far that has been tested. Anything not built is listed in the
**Roadmap** column in the future tense and is not a claim about current behaviour. “Implemented” means code exists and is
covered by the automated tests listed in QA.md; it does not mean validated on customer infrastructure.

| Area | Status | Tested / measured | Limits | Roadmap |
|---|---|---|---|---|
| Collection | Implemented: file imports (nmap, CSV, AWS/Azure/OCI/Kubernetes JSON, scanner CSV/JSON, Trivy, Grype), HTTP JSON poller, authorised TCP-connect discovery with an allowed-CIDR setting, manual API. Re-importing the same file is idempotent. | Unit and API tests; local IoT emulators and a loopback TCP scan. | No live cloud-SDK, VMware or endpoint-agent connectors. | DEEPSIGHT will gain native cloud and virtualization connectors. |
| Normalization | Implemented: quality flags for invalid, missing, stale, future, duplicate and unverified-source records; raw record kept. | Malformed-input tests. | — | — |
| Identity resolution | Implemented: logistic model plus hard rules; confirmed / probable / unresolved / potentially separate; merge and revert with a snapshot; indexed hostname blocking for candidate generation. | 16 hand-labelled pairs the training generator did not produce: precision 1.000, recall 0.778, false-merge rate 0.000. Candidate lookup on 5,001 synthetic assets: see QA.md. | Training data is synthetic. 16 pairs is too few to claim real-world accuracy. No automatic retraining on analyst decisions. | DEEPSIGHT will retrain on accumulated analyst decisions and report drift. |
| Temporal history and lifecycle | Implemented: change log, lifecycle states, relationship validity periods, raw-evidence archiving after a retention window. | Tests, including an archive round trip. | One relational store (NetworkX over relations); no separate time-series or graph database. | — |
| Data freshness | Implemented: per asset, last successful observation, sources that saw it, expected sources that did not, conflicting evidence; “no vulnerability detected” is separate from “not recently assessed”; threshold is a setting. | Tests for partial, failed, future-dated and unverified scans. | Only an observation that declares a complete, successful vulnerability assessment counts. Scanner CSV imports cannot declare that, so demo assets read “not recently assessed”; Trivy/Grype imports can. | — |
| Security intelligence | Partial: seed catalog (18 entries, including IoT/embedded entries with illustrative version ranges), version matching, scanner findings, CISA KEV sync and per-CVE NVD fetch (internet needed), NVD JSON import with CPE applicability matching. | CPE bounds and compound conditions tested on fixtures. KEV/NVD network sync was not exercised. | Seed entries are a snapshot. No threat-actor or IOC feeds. | DEEPSIGHT will pull NVD and KEV continuously and add threat-intelligence feeds. |
| Contextual risk | Implemented as an **explainable weighted heuristic** (CVSS, KEV, exploit availability, exposure, criticality, blast radius, recent change, anomaly, configuration weakness, EPSS). Shown beside CVSS with factors, confidence and basis. | Factor and staleness tests. | Uncalibrated; not a probability of compromise. EPSS values are imported by an administrator; missing or stale EPSS is not evidence of low likelihood. | DEEPSIGHT will blend in a validated ML factor once outcome data exists. |
| ML exploitation model (CISA KEV label) | **Not built.** | — | — | DEEPSIGHT will train on public data (label = KEV membership; CVSS vector, CWE, CVE age, vendor; time-based split), report AUC, and blend it in as a labelled ML factor separate from the heuristic. |
| Remediation workflow | Implemented: owner, due date, guidance, ticket link (http/https), status, accepted-risk and false-positive states with reason, approver and expiry (expired exceptions reopen); closure only through a newer, recent, successful verification scan that covers the finding, with before/after evidence; time to fix, SLA breaches, aging, risk removed per fix; what-if view. | Workflow, closure and inventory-change tests. | Ticket references are links only; no two-way Jira/ServiceNow sync. What-if uses heuristic scores, not predicted incident reduction. | DEEPSIGHT will create and synchronise tickets in external trackers. |
| IoT / embedded | Implemented: exposed management interfaces, end-of-life firmware, Telnet, FTP, cleartext MQTT, RTSP without authentication, raw print and Winbox are findings of their own (`DS-IOT-*`) with explainable factors, independent of CVE matches. Synthetic IoT demo devices and a Docker lab (three emulators and a real Mosquitto broker). | Policy tests for every rule; emulator and loopback-scan tests. The full four-container lab was not started in this recovery. | Firmware matching depends on an inventory feed; TCP discovery reads banners on a few ports only. | DEEPSIGHT will fingerprint firmware from passive and active discovery. |
| Anomaly detection | Implemented: Isolation Forest on change vectors, bootstrap plus platform-baseline retraining, analyst labels stored. | 12 hand-labelled change events: precision 0.714, recall 1.000, false-alert rate 0.286. | Small fixture; weak cold start. An anomaly warrants review and is not proof of malice. | DEEPSIGHT will use analyst labels for supervised evaluation and tuning. |
| ML validation and effectiveness | Implemented: fixed evaluation sets stored as model runs; analyst feedback reported as its own cohort and in a combined view; Effectiveness page (identity, anomaly, duplicate reduction, investigation duration, remediation). | Fixed evaluation reproduced by `scripts/measure_evaluation.py`. | One simulated false-positive review is the only feedback cohort in the saved exercise; it demonstrates the mechanism, not an improvement. Time saved is unmeasured. | DEEPSIGHT will report effectiveness from real analyst outcomes. |
| Analyst workflow | Implemented: prioritized work queue with “why this needs attention”, saved filters, global search, atomic bulk triage. | API tests; browser walk through. | Search is substring matching over names, owners, IPs, CVEs, titles. | — |
| AI assistant | Implemented: evidence mode (deterministic retrieval and explanation) or Claude tool-use mode with an API key. Read-only. Asset text is treated as untrusted data and citations are checked against an allow-list. | Four fixed questions must cite stored evidence; injection/citation test. | Claude mode was not exercised. Four questions is a smoke test, not a quality benchmark. | — |
| Coverage and integrations | Implemented: CMDB reconciliation (in CMDB never seen, seen not in CMDB, no owner), candidate attack paths from internet-exposed to critical assets over recorded relationships, outbound webhooks for new critical/KEV findings with durable outbox, de-duplication and bounded retries. | Fixture tests; browser walk through. | Attack paths are inferred from recorded dependencies, not validated reachability or exploit chains. A source is treated as the CMDB only if created with category `cmdb` (API). Webhook delivery to a real receiver was not exercised. | DEEPSIGHT will validate paths against network reachability data. |
| Reliability | Implemented: durable single-worker job queue with an independent heartbeat; schema-version migration for existing databases; backup and automated restore comparison; retention; health endpoint; Prometheus metrics; JSON logs; rate-limiter eviction; distinct error for undecryptable secrets. | Tests; backup restored from SQLite to SQLite and to PostgreSQL 16 with every table compared. | Single app replica. Backup file is unencrypted JSON holding password hashes and the secret key. | DEEPSIGHT will support multiple workers and encrypted backups. |
| Scale | Measured, small: 1,000 and 5,001 synthetic assets ingested on local SQLite with no failures (figures in QA.md). | `scripts/load_test.py`. | Single process, synthetic identities, no network collectors, no findings or graph edges. Not a capacity statement. | DEEPSIGHT will be load-tested on PostgreSQL with realistic findings and relationships. |
| Security | Unchanged from 1.0.2: JWT sessions, four roles, audit log, encrypted secrets, rate limits, CSP. Out of scope for 1.1.0. | Protected-function comparison to the 1.0.2 archive (saved, historical). | **Open: `pip-audit` reports 16 PyJWT 2.12.1 advisories.** No SSO/MFA/TLS termination (use a reverse proxy). | DEEPSIGHT will upgrade PyJWT and add SSO/MFA in a separately tested security change. |
| Demo and packaging | Implemented: offline Swagger UI, one-command demo script, “Reset demo” button, pinned dependencies, dev requirements, CI workflow. | Offline docs asset check; UI reset exercised in a browser. | The Docker image and CI workflow were not run in the final pass. | — |
